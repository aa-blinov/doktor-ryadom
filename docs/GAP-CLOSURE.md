# Что добавлено после сравнения с конкурентами

## Для пациента

- Ежедневная отметка сохраняет черновик на сервере. После возвращения можно продолжить; исправление готовой записи сохраняет предыдущую версию.
- В плане врача собраны рекомендации, цель наблюдения, следующий приём и согласованный способ связи.
- GAD-7 и PHQ-2 появляются по назначению врача. Ответы сохраняются отдельно от ежедневного дневника; приложение не ставит диагноз по баллам.
- Назначения лекарств содержат инструкции врача. Пациент отмечает приём или пропуск; «не понадобился» доступно только для назначения по необходимости. Наблюдения сохраняются без утверждений о причине симптома.
- Сводка перед приёмом включает дневник, опросники, назначения, отметки и рекомендации. Отправленная версия не изменяется при последующих правках дневника. Доступны текст, CSV и печать в PDF через браузер.
- Настройки позволяют изменить пароль, завершить другие сеансы, скачать данные, создать резервные коды входа и удалить аккаунт. Коды показываются один раз и хранятся только в виде хешей.

## Для врача

Новые сводки и результаты опросников выделены в списке пациентов. Просмотр подтверждается отдельным действием. Врач назначает опросники, сохраняет рекомендации после приёма и ведёт назначения лекарств. Самостоятельно выбранная роль врача не подтверждает квалификацию: новые приглашения доступны после проверки администратором.

## Напоминания и эксплуатация

Push включается пациентом для конкретного устройства. Письма и ежедневная сводка новых результатов для врача требуют отдельного согласия. Сообщения не содержат медицинских подробностей. Расписание учитывает часовой пояс и паузу; повторные отправки за день подавляются.

SQLite копируется ежедневно с проверкой целостности; локальные копии хранятся семь дней. Экспорт и удаление доступны без обращения в поддержку. При удалении врача медицинские записи пациента сохраняются с обезличенным автором.

## Что ещё нужно для реального использования

Яндекс SMTP подключён: авторизация прошла, тестовое письмо принято сервером с ответом 250 OK. Получение во входящих ещё нужно подтвердить. Подтвердить размещение основной базы и резервных копий в Казахстане, согласовать документы оператора и клинический порядок реагирования. Проверить push на реальных устройствах и настроить резервную копию вне этого сервера. Полный PHQ-9 с вопросом о самоповреждении требует согласованного процесса реагирования; сейчас используется PHQ-2.
