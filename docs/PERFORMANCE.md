# Загрузка карточки врача

Профилирование 8 октября 2026 года выполнено в Chrome через CDP с замедлением CPU в четыре раза. Сервер работает на синтетической SQLite-фикстуре с одной дневниковой записью; ширины окна — 1440 и 320 px. Service worker заблокирован. Это локальный сценарий, а не измерение рабочего сайта.

Таблица относится к исходному уточнению сводки до добавления мобильного меню. Сохранённая запись агрегатов: `.impeccable/review/summary-profile-refinement-measurements.json`.

| Показатель | До | После |
| --- | ---: | ---: |
| API-запросы до открытия обзора | 4 | 2 |
| Узлы DOM при открытии обзора | 748 | 179 |
| Максимальная длинная задача, 1440 px | 779 мс | 115 мс |
| Максимальная длинная задача, 320 px | 484 мс | 62 мс |
| Время сценария открытия, 1440 px | 2626 мс | 1644 мс |
| Время сценария открытия, 320 px | 1572 мс | 1077 мс |

Каждое значение получено в одном прогоне. Время сценария включает переход, перезагрузку, ожидание заголовка и фиксированную паузу 400 мс; это не отдельная метрика отрисовки. В мобильном исходном профиле наблюдатель продублировал некоторые длинные задачи: сопоставляется только максимум, суммарное время и число задач не сравниваются. Длинные задачи остаются и после правки.

Изначально карточка монтировала все вкладки, включая опросники, и запрашивала список пациентов. Теперь вкладки монтируются при первом открытии; посещённые вкладки сохраняют формы, отдельно для каждого пациента. Список запрашивается только на маршруте списка. До открытия обзора остаются `/api/me` и данные пациента; последующее явное открытие опросников запрашивает библиотеку опросов. Сериализация всего содержимого сводки для сопоставления отправки выполняется только у пациента. Начальный обзор содержит меньше разделов; расчёты остаются доступными в подробностях.

API завершает ожидание через 20 секунд, включая чтение тела ответа. Автоматических повторов нет. Тайм-аут записи не доказывает, что сервер её не сохранил: сообщение предлагает обновить страницу и проверить результат перед повтором.

## Воспроизведение

Из каталога `app/`:

```sh
npm run build
npx vitest run tests/summary-profile.test.ts
```

Тест по умолчанию проверяет текущую версию и обновляет `.impeccable/review/summary-profile-after.json` и снимки `summary-after-*.png`. Последующие прогоны перезаписывают этот файл уже с мобильным меню и могут выполняться при параллельной нагрузке; новые сырые значения могут отличаться от исторической таблицы. Для её проверки используйте сохранённую запись агрегатов, а не последний файл `summary-profile-after.json`. Исходные данные сравнения сохранены в `.impeccable/review/summary-profile-before.json`. Переменная `PROFILE_PHASE=before` использовалась для захвата прежней сборки; она меняет режим теста и имя артефакта, но не восстанавливает старый код или старую сборку.

## Границы результата

Замедление CPU и узкое окно не заменяют физическое мобильное устройство. Lighthouse и реальный INP не измерялись. Одна запись не проверяет большие истории, нестабильную сеть или все причины зависаний в рабочей среде. Предупреждение Vite о JS-бандле около 755 КБ остаётся. Измерения подтверждают уменьшение начальной работы в этом сценарии; обещания устранить все зависания или обеспечить конкретный процент ускорения из них не следуют.
