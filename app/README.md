# Рядом

PWA для коротких отметок состояния и сопровождения между приёмами. React + TypeScript + Mantine, Hono API, D1 (SQLite), Drizzle migrations. Экраны описаны в [../docs/SCREENS.md](../docs/SCREENS.md).

## Локальный запуск

```sh
npm ci
npm run db:migrate
npm run build
npm run dev:server
```

Wrangler открывает приложение на `http://localhost:8787`. Для разработки интерфейса запустите во втором терминале `npm run dev`: Vite проксирует API к Wrangler. База хранится локально в `.wrangler/` и сохраняется между запусками.

```sh
npm run check
npm test
node scripts/integration.mjs
```

Тесты `npm test` проверяют API на настоящей SQLite через адаптер D1 и браузерные сценарии Chromium. Браузерный тест использует системный Chromium, если доступен, иначе браузер Playwright (`npx playwright install chromium`). Путь можно задать через `CHROME_EXECUTABLE`. Перед ним нужна `npm run build`. Тестовые записи синтетические и не отправляются во внешнюю базу.

Последняя команда требует работающего Wrangler и создаёт только синтетические тестовые аккаунты. Чтобы использовать адрес localhost, задайте `TEST_BASE_URL=http://localhost:8787`.

## Что работает

Регистрация по email и паролю, вход/выход, серверные сессии; две роли; одноразовые приглашения и отдельное согласие пациента; одна отметка в день; история и CSV; настройка врачом плана; практики и оценка переносимости; пауза расписания; отзыв доступа. Врач получает доступ к прошлым и новым записям только активного подключённого пациента.

Пароли: scrypt с индивидуальной солью. Сессии: случайные токены в HttpOnly/SameSite cookie, в базе только SHA-256 отпечатки. API: no-store, проверка Origin, ограничения размера, серверная проверка ролей и доступа, лимит попыток входа. Клинические записи не кешируются service worker и не записываются в localStorage. Офлайн доступны только оболочка и статические ресурсы; API требует интернет.

## Границы первой версии

Email не подтверждается; восстановление пароля, MFA, проверка статуса врача, фоновые push, медицинская валидация правил, история редакций плана и управление удалением аккаунта не реализованы. Пациенту явно показан режим просмотра данных; уведомления экстренного реагирования не обещаются. Настройки времени отображаются внутри приложения.

Перед использованием с реальными медицинскими данными требуются клиническая проверка содержания, выбор страны и размещения данных, согласованные документы обработки данных и проверка безопасности. Это рабочая первая сборка для оценки сценариев, а не подтверждённая медицинская система.

## Размещение

Сборка создаёт `dist/client` и Worker ESM в `dist/server/index.js`. `.openai/hosting.json` задаёт Sites и логический binding `DB`; миграции `drizzle/*.sql` применяются платформой при публикации. Не меняйте уже применённые миграции. Локальный `database_id` в `wrangler.jsonc` — заглушка, не production ID.

Описание для психиатра: [методика по экранам](../docs/METHODOLOGY.md).

Запуск на этом сервере: [Docker Compose и общий Caddy](../deploy/README.md). Контейнер использует Node.js и постоянную SQLite-базу, без зависимости от D1.
